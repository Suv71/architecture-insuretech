**Предлагаемое решение:**

- Так как сервис **ins-comp-settlement** получает данные по всем оформленным за день страховкам из сервиса **core-app**, то это может сильно нагрузить сервис **core-app**. Для уменьшения нагрузки и постепенного получения данных предлагается создать топик в Kafka для событий об оформленных страховках и записывать туда информацию. Для записи хорошо подойдет Transactional Outbox, чтобы не потерять события. Сервис **ins-comp-settlement** будет считывать события и прихранивать у себя, а затем использовать для финальных расчетов за день.

- Сейчас сервис **ins-product-aggregator** испытывает проблемы при получении данных из внешних систем, соотвественно страдают и потребителя этих данных **core-app** и **ins-comp-settlement**. Рост количества внешних систем еще более негативно скажется общей работе систем. Чтобы решить данную проблему можно завести крон в сервисе **ins-product-aggregator**, который будет опрашивать все доступные внешние системы и формировать текущий слепок по продуктам и тарифам. Если данный слепок имеет отличия от предыдущего, то текущие данные отправляют в соотвествующий топик Kafka, откуда их вычитывают сервисы **core-app** и **ins-comp-settlement** и используют для своих нужд. Для записи слепка в Kafka также нужно использовать Transactional Outbox.
